# v0.1 Completed Foundation Plan — mcp-evals

**Status:** Completed

---

## 1. Executive Summary

Deliver a **minimal viable open-source foundation** for behavioral evaluation of MCP (Model Context Protocol) servers. v0.1 focuses on static tool-description linting and eval-spec validation — zero LLM cost, CI-ready from day one.

---

## 2. Problem Statement

- MCP protocol conformance tools verify JSON-RPC correctness only
- No standard way to test whether LLMs select the correct tool or pass valid arguments
- Tool descriptions are load-bearing API design with no linting or regression testing

---

## 3. Goals (v0.1)

| # | Goal | Status |
|---|------|--------|
| G1 | Provide CLI installable Python package | Done |
| G2 | Lint MCP tool descriptions from YAML fixtures | Done |
| G3 | Validate eval suite YAML structure | Done |
| G4 | Docker-based dev and test environment | Done |
| G5 | Contributor-ready repo (README, CI, LICENSE) | Done |

## 4. Non-Goals (v0.1)

- Live MCP server connection (stdio/HTTP)
- LLM-based tool-selection benchmarking
- GitHub Action with PR comments
- Multi-turn conversation evals
- Resource/prompt endpoint support

---

## 5. Architecture Delivered

```
CLI (Click)
  ├── lint          → linter/descriptions.py
  ├── validate-spec → runner/eval_runner.py (dry-run)
  └── health        → config validation

Models (Pydantic v2)
  ├── EvalSuite / EvalCase
  └── ToolCatalog / ToolDefinition

Infrastructure
  ├── structlog logging
  ├── pydantic-settings config
  └── Docker Compose (test, lint-example)
```

### Technology Choices

| Layer | Choice | Rationale |
|-------|--------|-----------|
| Language | Python 3.11+ | MCP SDK ecosystem, pytest integration |
| CLI | Click | Mature, composable |
| Validation | Pydantic v2 | Strict schemas, good errors |
| Logging | structlog | Structured JSON-capable logs |
| Packaging | hatchling | Modern pyproject.toml builds |
| Quality | ruff, mypy, pytest | Standard Python OSS toolchain |
