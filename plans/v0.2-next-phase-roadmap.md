## 1. Executive Summary

Evolve mcp-evals from a **static linter** into a **behavioral eval platform** for MCP servers: connect to live servers, run tool-selection benchmarks against real LLMs, and gate CI with pass/fail thresholds.

## 3. Milestone Breakdown

### Milestone M1 — MCP Client Integration (v0.2.0)

**Goal:** Connect to real MCP servers and discover tools dynamically.

#### Deliverables

- [ ] `mcp_evals/mcp_client/transport.py` — stdio and Streamable HTTP transports
- [ ] `mcp-evals discover <server-config>` — list tools from live server
- [ ] `mcp-evals lint --live` — lint discovered tools without YAML fixture
- [ ] Server config YAML: command, args, env, transport type
- [ ] Integration test with a minimal reference MCP server in `examples/`

#### Acceptance Criteria

- AC1: Discover tools from a local stdio MCP server in <5s
- AC2: Lint results match fixture-based lint for same tool definitions
- AC3: Graceful error when server fails to start or handshake fails

#### Dependencies

- `mcp` Python SDK (optional extra `[mcp]`)
- Reference MCP server for CI (e.g., minimal calculator server)

#### Risks

| Risk | Mitigation |
|------|------------|
| MCP spec churn | Pin protocol version; conformance test in CI |
| Flaky stdio servers | Retry + timeout config; health pre-check |

**Estimate:** 1–2 weeks

---

### Milestone M2 — LLM Eval Runner (v0.2.0)

**Goal:** Run eval cases against a configurable LLM and measure tool-selection accuracy.

#### Deliverables

- [ ] `mcp_evals/runner/llm_runner.py` — model call loop with tool definitions
- [ ] `mcp-evals run <suite.yaml> --model gpt-4o-mini` — execute behavioral evals
- [ ] Metrics: selection accuracy, argument validity, latency per case
- [ ] Repeated sampling (`--samples 3`) for nondeterministic models
- [ ] Ollama/local model support via OpenAI-compatible endpoint
- [ ] `--pass-threshold 0.8` exit code for CI

#### Acceptance Criteria

- AC1: Run 10-case suite against Ollama locally without cloud API key
- AC2: Report shows per-case pass/fail with expected vs actual tool
- AC3: Exit code 1 when accuracy below threshold

#### Dependencies

- litellm or direct OpenAI/Anthropic SDK
- Eval suite YAML from v0.1 (no schema change)

#### Risks

| Risk | Mitigation |
|------|------------|
| CI cost from LLM calls | Default to Ollama in CI; cache results option |
| Nondeterministic results | Multi-sample + confidence interval in report |

**Estimate:** 2–3 weeks

---

### Milestone M3 — GitHub Action (v0.3.0)

**Goal:** One-line CI integration for MCP server repos.

#### Deliverables

- [ ] `action.yml` — composite GitHub Action
- [ ] Inputs: `suite`, `catalog`, `model`, `threshold`, `api-key` (secret)
- [ ] PR comment with markdown report (selection accuracy delta)
- [ ] Workflow example in `examples/github-action/`

#### Acceptance Criteria

- AC1: Action fails PR when selection accuracy drops below threshold
- AC2: PR comment renders readable markdown table
- AC3: Works on `ubuntu-latest` with Ollama service container option

**Estimate:** 1 week

---

### Milestone M4 — Linter Expansion (v0.3.0)

**Goal:** Catch more description issues that cause agent confusion.

#### New Rules

| Rule | Severity | Description |
|------|----------|-------------|
| `ambiguous-verbs` | warning | Multiple tools use same action verb (get/fetch/list) |
| `missing-examples` | info | Complex parameters lack example values |
| `name-description-mismatch` | warning | Tool name implies different action than description |
| `required-params-undocumented` | error | Required param missing type or description |

**Estimate:** 1 week
